# PyVista front-view comparison

This document explains how to render and compare:

- the original textured GLB from `eval_6cases`
- the OBJ/MTL/texture output generated by the C++ 3DTexture pipeline

The comparison uses PyVista for rendering and trimesh only for asset loading.
It does **not** use the original C++ renderer, OpenCV, or Open3D.

---

## 1. What it compares

For every case, the tool renders two images:

1. **Original GLB**
   - loads `<case>_textured.glb`
   - extracts the base-color texture
   - ignores normal, metallic, roughness, and emissive maps

2. **Generated result**
   - loads `result.obj`, `result.mtl`, and the texture pages
   - extracts only the base-color texture
   - ignores all other material channels

Both meshes are rendered from the same front-view camera, at the same world
scale, with lighting disabled.

The generated side-by-side image is:

```text
Original GLB | 3DTexture
```

---

## 2. Requirements

### System

- Linux
- Python 3.10 or newer
- System VTK (`python3-vtk` on Ubuntu)
- `xvfb-run` if rendering on a headless machine

### Python

The optional renderer environment installs:

- `pyvista`
- `trimesh`
- `pygltflib`
- `numpy`
- `pillow`

PyVista is installed with `--no-deps` so the renderer reuses the system VTK
installation instead of downloading a second VTK wheel.

---

## 3. Install

From the repository root:

```bash
./scripts/install_pyvista_renderer.sh
```

This creates:

```text
.venv-pyvista/
```

The script verifies that PyVista, trimesh, and VTK are importable.

To activate the environment manually:

```bash
source .venv-pyvista/bin/activate
```

## 4. Run

### 4.1 Basic usage

```bash
./scripts/compare_eval6_front.sh \
    /mnt/c/Users/JdSc-local/Downloads/eval_6cases.zip \
    /home/jdsc-local/tmp/3dtexture-eval6-full
```

Arguments:

```text
DATASET   eval_6cases.zip or an extracted eval_6cases/ directory
RESULTS   output root containing one directory per case
OUTPUT    optional output directory
```

If `OUTPUT` is omitted, images are written to:

```text
<RESULTS>/front_compare/
```

---

### 4.2 High-resolution rendering

Use `--size` to increase the resolution of each side.

Default:

```bash
--size 1024
```

High-resolution example:

```bash
./scripts/compare_eval6_front.sh \
    /mnt/c/Users/JdSc-local/Downloads/eval_6cases.zip \
    /home/jdsc-local/tmp/3dtexture-eval6-full \
    /home/jdsc-local/tmp/3dtexture-eval6-full/front_compare_2048 \
    --size 2048
```

Output image sizes:

| `--size` | Each side | Combined side-by-side image |
|---:|---:|---:|
| 1024 | 1024 × 1024 | 2048 × 1024 |
| 2048 | 2048 × 2048 | 4096 × 2048 |
| 4096 | 4096 × 4096 | 8192 × 4096 |

---

### 4.3 Render a single case

```bash
./scripts/compare_eval6_front.sh \
    DATASET \
    RESULTS \
    OUTPUT \
    --case 20260928-165519
```

`--case` may be repeated:

```bash
--case CASE_A --case CASE_B
```

---

### 4.4 Generate a difference image

```bash
./scripts/compare_eval6_front.sh \
    DATASET \
    RESULTS \
    OUTPUT \
    --diff
```

This additionally writes:

```text
<case>_<view>_diff.png
```

The difference image is amplified by 4× to make small color changes visible.

---

### 4.5 Choose another view

The default view is `front`.

To render another view from `render_manifest.json`:

```bash
./scripts/compare_eval6_front.sh \
    DATASET \
    RESULTS \
    OUTPUT \
    --view back
```

The view name must match the `label` field in:

```text
rank_000/controls/render_manifest.json
```

---

### 4.6 Generate novel views

To render multiple new views that do **not** overlap the original selected
views:

```bash
./scripts/compare_eval6_front.sh \
    DATASET \
    RESULTS \
    OUTPUT \
    --novel-views 8
```

This renders 8 additional viewpoints per case.

The tool reads the original selected views from:

```text
rank_000/controls/selected_views.json
rank_001/controls/selected_views.json
rank_002/controls/selected_views.json
rank_003/controls/selected_views.json
```

It then generates evenly distributed novel viewpoints on the sphere and avoids
the original viewpoints by at least:

```text
--novel-min-angle 12
```

You can change the separation:

```bash
--novel-min-angle 20
```

Example with 12 novel views and a 20-degree separation:

```bash
./scripts/compare_eval6_front.sh \
    DATASET \
    RESULTS \
    OUTPUT \
    --novel-views 12 \
    --novel-min-angle 20
```

Novel view images are named:

```text
<case>_novel_00.png
<case>_novel_01.png
<case>_novel_02.png
...
```

Each novel view still renders both:

```text
Original GLB | 3DTexture
```

The selected azimuth and elevation for every novel view are recorded in
`summary.json`.

## 5. Output files

For each case, the tool writes:

```text
<case>_<view>_original.png
<case>_<view>_result.png
<case>_<view>.png
```

It also writes:

```text
contact.png
summary.json
```

### 5.1 `<case>_<view>.png`

A side-by-side image:

```text
Original GLB | 3DTexture
```

### 5.2 `contact.png`

A contact sheet with all rendered cases.

Layout:

```text
Original GLB | 3DTexture
Original GLB | 3DTexture
...
```

### 5.3 `summary.json`

Records:

- dataset path
- results path
- output path
- view name
- view count
- unique case count
- resolution
- color mode
- whether lighting and PBR maps are disabled
- novel view count and minimum separation
- per-view output paths
- MAE, RMSE, and PSNR

Example:

```json
{
  "view": "front",
  "resolution": 2048,
  "color_mode": "base_color",
  "lighting": false,
  "normal_maps": false,
  "metallic_roughness": false,
  "case_count": 6,
  "success_count": 6,
  "failure_count": 0,
  "cases": [
    {
      "id": "20260928-165519",
      "success": true,
      "mae": 3.577,
      "rmse": 11.129,
      "psnr": 27.2
    }
  ]
}
```

## 6. Color and brightness behavior

The renderer is intentionally conservative:

```text
lighting       disabled
PBR            disabled
ambient        1.0
diffuse        0.0
specular       0.0
opacity        1.0
smooth shading disabled
```

PyVista still combines `ambient` and `diffuse` even when lighting is disabled.
Setting both to `1.0` would double-count the base color and make the image too
bright.  The current settings render the raw base-color texture without an
additional lighting contribution.

Textures are also treated as display-space base colors:

```text
texture.use_srgb_color_space = False
```

This avoids an unwanted gamma conversion in the offscreen render.

## 7. Camera and geometry alignment

The renderer reads the front camera from:

```text
<case>/rank_000/controls/render_manifest.json
```

It parses:

```text
camera_to_world
render_ortho_scale
camera_fit.distance
```

The camera matrix columns are interpreted as:

```text
right
up
backward
camera position
```

The camera is configured as:

```text
position       = camera_center
focal point    = camera_center - backward * distance
view up        = up
projection     = orthographic
parallel scale = render_ortho_scale / 2
```

### Coordinate normalization

The original GLB is converted from source coordinates to render coordinates:

```text
render_x =  source_x
render_y = -source_z
render_z =  source_y
```

The original mesh is then normalized to height `1.0` in the render coordinate
system, matching the normalization used by the C++ pipeline.

The generated `result.obj` is already in that normalized render space, so it is
used directly.

This keeps the original GLB and the generated OBJ aligned in the same camera.

---

## 8. Metrics

For every case, `summary.json` records:

- **MAE** — mean absolute RGB error
- **RMSE** — root mean square RGB error
- **PSNR** — peak signal-to-noise ratio

These metrics compare the two rendered RGB images after alignment.  They are
intended as a coarse color-fidelity indicator, not as a full perceptual metric.

## 9. Troubleshooting

### `import vtk` fails

Install system VTK:

```bash
sudo apt-get install python3-vtk
```

Then rerun:

```bash
./scripts/install_pyvista_renderer.sh
```

---

### Rendering fails on a headless machine

Install `xvfb`:

```bash
sudo apt-get install xvfb
```

The wrapper automatically uses `xvfb-run` when `DISPLAY` is empty.

---

### Missing original GLB

Check that the dataset contains:

```text
eval_6cases/<case>/mesh/<case>_textured.glb
```

---

### Missing result OBJ

Check that the results root contains:

```text
<results>/<case>/result.obj
<results>/<case>/result.mtl
<results>/<case>/*.png
```

---

### View name is invalid

List the available view labels from:

```text
rank_000/controls/render_manifest.json
```

Then pass one of those labels to `--view`.
